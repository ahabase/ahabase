# ahabase Transparency Blueprint

> How the package makes an Epic's consistency visible: the ontology map generated into the index, and the lineage from concept to code checked in both directions.

**Implements:** [ontology-lineage-blueprint](ontology-lineage-blueprint), [ontology-projection-blueprint](ontology-projection-blueprint) - within [implementation-ahabase-architecture-blueprint](implementation-ahabase-architecture-blueprint)
**Story:** [AHA-0009](AHA-0009)
**Code:** epic, ontology_map, lineage, cli_transparency, capabilities, containment

## Overview

Two commands over one reading of the Epic's tree, standard library only (click for the door):

- `ahabase ontology graph [--root DIR] [--check]` - builds the ontology map and writes it between the ontology-map markers of the ontology index (a new `## Ontology map` section before `## Related` the first time); `--check` writes nothing and exits 1 with a diff when the block is stale or edited by hand.
- `ahabase verify [--root DIR]` - computes the Epic-scope lineage and prints the table, the absences, the document blueprints and the divergences; exits 1 on any divergence.

Exit codes of both: 0 holds, 1 a finding, 2 a usage problem or a tree that is not an Epic.

## Reading the tree (`epic`)

The Epic is the directory with `_grid4d/`; its identity is the one story document with `**Type:** Epic`; `**CodeArtifacts:**` names the package directory inside the Epic. A missing identity, a missing or outside `CodeArtifacts` is a usage problem (exit 2), never a silent empty result.

## The ontology map (`ontology_map`)

- **Facets** - the `###` headings of the index's `## Vocabulary`, in order; their links to `ontology-*` blueprints are the nodes.
- **Edges** - every Relations bullet of the form ``- **relation** → [Target](ontology-target-blueprint)`` (notation shown as code, not a link) whose source and target are both nodes; bullets to anything else (a plain word, a method's concept) are not edges.
- **Rendering** - a mermaid `flowchart LR`, one `subgraph` per facet; node ids are the stems with `_` for `-`.
- **Idempotent** - the block is replaced between the markers, nothing outside them changes; a second run writes the same bytes (measured by the story's tests).

## The lineage (`lineage`)

The joins and classes are those of [ontology-lineage-blueprint](ontology-lineage-blueprint). Modules are every `*.py` under the package, named by their dotted path relative to it (`__init__`, `safe`, `sub.module`), so a nested module joins through its `**Code:**` entry as well as its back-link. The back-link is read from the module docstring (parsed, not grepped), so a comment cannot stand in for it.

## Rules

1. **Build in the package, not in the method** - the design of the AHA-0008 transparency lane: base territory by the boundary criterion; one place per capability; the computation is small; the method's generators keep working beside it (strangler fig).
2. **Absences are reported, divergences fail** - agreed with the design consult (seat e962e97f): a concept's absence depends on its State, which is a judgment; a divergence is a contradiction between two declarations, which is not.
3. **No page of the method's generator** - the Epic's projections declaration lists none, because those pages name documents of the closed zone; the Epic's own projections are generated by this package.
4. **Read only, except the map** - `verify` never writes; `ontology graph` writes only between its markers, and markers that are present but not one balanced pair (a lone, doubled or reversed marker) stop it with exit 1 - no markers at all is the first run, which adds the section before anything is written - a guess could replace hand text between a stray marker and the real one (local review of AHA-0009).
5. **A State is a declaration** - a concept whose State says "implemented" in full while no blueprint implements it is a divergence, like an Implements link to a concept that does not exist (local review of AHA-0009); "implemented in part", "defined" and "planned" admit an absence.

## Structure

`src/ahabase/epic.py` (the Epic's tree: identity, `CodeArtifacts`), `src/ahabase/ontology_map.py` (the map: facets, relations, rendering, the markers), `src/ahabase/lineage.py` (joins, classes, the report), `src/ahabase/cli_transparency.py` (the two commands, added to the CLI by `cli.py`); tests in `tests/test_transparency.py` on fictional Epic trees.

## Template

What an Epic declares so that the lineage can join it:

```markdown
**CodeArtifacts:** src/<package>                     <- in the Epic identity

**Implements:** [ontology-<concept>-blueprint](ontology-<concept>-blueprint)
**Code:** <module>, <module>                         <- in an implementation blueprint
**Code:** none (document blueprint)                  <- or, for a document by design
```

```python
"""<What the module does.>

Implements: implementation-<epic>-<name>-blueprint
"""
```
