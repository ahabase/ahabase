# Knowledge map links a document of another repository

> The map hook records a document read from evolucean's repository with a path-prefixed link, in a map that is written as public and whose links are bare names.

**Status:** open
**Priority:** medium

## Problem

Found in [AHA-0003](AHA-0003), 2026-10-25, by the local review seat. Reading the foundation roadmap, which lives in evolucean's repository, during a story of this Epic made the knowledge-map hook add a Consumed entry whose link carries a path prefix (`evolucean/<name>`). Two rules meet here:

1. Links in `_grid4d` are bare file names; a path-prefixed link does not resolve in the flat wiki.
2. This Epic's knowledge is written as if public; a link that names a document of the closed method points outside the public perimeter.

The map is generated by the hook and is not edited by hand, so the entry stays in this story's map until the generator is fixed. A related gap: the story tests check that links exist, not that they resolve within this repository.

## Expected

The generator records a document of another repository of the lineage either not at all in a map of a public-bound Epic, or as plain text without a link, as the containment rules of evolucean decide. A check over this Epic's `_grid4d` reports links that do not resolve within the repository, except the links to the shared story and blueprint vocabulary evolucean provides.

## Fix

In evolucean's repository (the surface rule: evolucean's internals are described there) - handed to evolucean's next story, roadmap step 6.
