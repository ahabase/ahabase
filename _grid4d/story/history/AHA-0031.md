# AHA-0031: the consumer playground: a standalone ahabase workspace for plug-and-play Epics and request stories

> a separate Claude Code workspace whose primary tool is the ahabase CLI alone

**Type:** default
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** [implementation-story-blueprint](implementation-story-blueprint)
**Follows:** AHA-0030

## Goal

Prove standalone ahabase as the primary tool of its own workspace: a consumer playground (a sibling of the development workspace, outside every private repo) where an existing plug-and-play repository registers as a new Epic and stories carry the request archetypes a real consumer brings. The development seat stays in the evolucean-workspace; the playground is the consumer seat, and nothing of the evolucean agent layer carries it.

## Requirements

### R1: the workspace bootstrap, versioned as an artifact

The bootstrap lives in the ahabase repository (a script, a workspace CLAUDE.md template, a scenarios document) and creates the live workspace at ~/ahabase-playground: the CLAUDE.md declaring ahabase the primary tool (written for this setup alone - nothing is copied from the development workspace), a venv with ahabase installed from the built wheel (never the checkout - the leg's isolation lesson; a pip show witness), AHABASE_WORKSPACE pinned to the workspace root (config.py's single workspace seam - one declaration, no detection), and a workspace .claude/settings.json allowlisting the wheel-installed ahabase binary (the seat runs without per-command permission prompts). The seat's memory starts empty by design: the playground proves ahabase self-describes a fresh agent through CLAUDE.md, CLI help, and story documents - if the seat keeps relearning the same facts, the fix lands in the package's self-description, never in hand-fed memory.

**Acceptance Criterion:** running the bootstrap produces the workspace net, each part witnessed: the CLAUDE.md declaring ahabase the primary tool exists, the venv serves ahabase from the built wheel (a pip show witness - the leg's pattern), the named entrypoint (the workspace's environment file) exports AHABASE_WORKSPACE pinned to the playground root, and the workspace .claude/settings.json allowlists the wheel-installed ahabase binary; the seat's memory directory holds nothing seeded (empty by design, a stated decision - no development-workspace memory copied). A probe run under that entrypoint's environment resolves config.py's get_workspace_dir() to the playground root - the single workspace seam, measured, not assumed.

### R2: the plug-and-play seam - an existing repo becomes an Epic

Two sample repositories mint by the bootstrap: a scratch repo (an empty git repository - no commits, no files; the consumer's first touch) and a messy one (code, its own default branch other than main, an existing tag sharing no `v<STORY>` name, an existing CI file). Each registers through ahabase init - the scratch from its empty state, the messy one as a non-empty repository - and validates green; the messy repo declares its branch and its CodeArtifacts line in its def file (the instruction lives in the init door's --help and its own code comment, not the post-init echo - the reviewer's probe; the scenarios doc writes the declaration, the package-independent lifecycle stays green either way) and a story completes onto that declared branch.

**Acceptance Criterion:** both repos are registered Epics (validate holds), and the messy repo's story lands on its own declared branch with tag and merge - not on main, measured three ways: the merge commit sits on the declared branch (git log --merges), the story tag resolves to the story branch tip (rev-parse), and main is absent or its ref unchanged across the run. The messy repo's pre-existing tag is untouched and the story tag is distinct (complete skips tagging when the name exists, so the fixture's tag shares no `v<STORY>` name). A control def file without **Branch:** lands the story on main and the branch check fails - the red arm that proves the check can fail.

### R3: request archetypes through the consumer seat

The scenarios document drives five request archetypes end-to-end with the ahabase CLI alone (no evolucean command exists in the playground): a docs-only story, a code-plus-tests story, a story sequence hitting the archive window (StoryHistoryKeep), a conflicted merge rehearsing complete's abort-and-recover path, and the refusals - the guard paths a consumer meets before any happy one: dirty main tree at create, root checked out on another branch than the declared one at complete, incomplete story set at complete. The conflict is real (the same lines edited on the declared branch and in the story worktree), never a mocked failure.

**Acceptance Criterion:** each happy archetype completes green (status, tag, merge, archive where declared) through story create/status/complete only - the archive row asserts the oldest story set moved to story/history/ and the newest stayed. The conflict scenario's refused complete leaves no MERGE_HEAD and a clean porcelain behind, the worktree and branch survive, and the error names the recovery; after the scenario resolves the conflict, the re-run completes with exactly one merge commit and one tag. Each refusal names its reason and writes nothing: no tag minted, Status unchanged, no merge commit.

### R4: isolation - the real workspace stays untouched

The playground writes nothing into the development workspace: after the full scenario pass, ~/ahabase holds no data directory, settings file, or session scope for any playground Epic. The forgotten-env control carries both arms, each a scripted row: the load-bearing arm sandboxes HOME, unsets AHABASE_WORKSPACE, runs a command that would write, and asserts the write lands under $HOME/ahabase - witnessing that a forgotten pin targets the real-workspace path, so the pinning matters; the held-seam arm pins AHABASE_WORKSPACE, runs the same scenario against the real HOME, and a scripted final check finds no playground writes under the real workspace's _data/ and _config/.

**Acceptance Criterion:** both control arms pass as rows of the tests definition: the load-bearing arm's would-be write lands under the sandboxed $HOME/ahabase (the default target measured, not assumed), and the held-seam pass leaves no playground entries under the real workspace's _data/ and _config/.

### R5: the comparison lens - the playground measures what the consumer lacks

The playground answers "what does the development workspace carry that a fresh consumer does not get?" as a measured, written gap report - never as ambient context (R1's empty-memory decision stands: nothing is inherited, the comparison is an explicit act). Two pieces: the reference shelf, built by a development-side script that reads the development workspace read-only and writes a sanitized snapshot into the playground's reference/ (the door census - the evolucean CLI's help tree against ahabase's, command group by command group; the development CLAUDE.md sanitized - no machine paths, no account names; the knowledge inventory - every registered Epic and its _grid4d folder counts; the memory index titles only, never bodies); and the gap walk, a scenarios chapter that has the playground seat walk its own surface (CLAUDE.md, CLI help, story documents) against each shelf item and write an English report classifying every row three ways - a package gap (the door or capability the ahabase package lacks; the open-source backlog's direct input), a self-description gap (the capability exists but the self-description does not tell the consumer), or dev-only by design (epic content, development practice, multi-instance machinery) - each row naming its evidence.

**Acceptance Criterion:** the shelf builds green into the playground's reference/ (idempotent - a re-run replaces it) and is sanitized: no machine paths and no account names anywhere in it (the census measures doors, not people). The scenarios document carries the gap-walk chapter with the three-way classification. A first walk exists as the versioned sample report, and it names every door group the census recorded - the suite row enforces the naming, so a census row with no report row is a stale walk, a red, not a silence. The shelf script writes nothing outside the playground's reference/ and never writes the development workspace.
