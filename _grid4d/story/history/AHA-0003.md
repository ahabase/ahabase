# AHA-0003: ahabase safe compare: fingerprint comparison of a stored secret with its current source, never printing a value; review nit of safe run; knowledge written as public

> The tool every shadow run needs: tell whether the safe holds the same value as the source a consumer reads today - without showing either value.

**Type:** default
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** [implementation-story-blueprint](implementation-story-blueprint)

## Goal

The secrets roadmap of the core Epic puts a shadow run before every switch of a consumer to the safe: the value is stored in the safe, then compared with the current source (an environment variable, a file, the credential of a git remote) without printing it. This story adds that comparison (roadmap step 1a). It also applies the remaining review nit of the safe and records in the Epic identity that its knowledge is written as if public. Nothing on the instance is switched; tests use fictional values only.

The story became the shaping place of the safe model with the Human (2026-10-25): a review of the model's robustness, consistency and sustainability (R4) and the direction that safe credential handling is the first, open capability of ahabase (R5).

## Requirements

### R1: `ahabase safe compare`

`ahabase safe compare NAME --env VAR | --file PATH | --git-remote REPO`: compares the stored value with the source by sha256 in constant time and prints only `NAME: same` or `NAME: different` - never a value and never a fingerprint (a fingerprint of a short password can be guessed). Exit 0 same, 1 different, 2 when either side is missing or the number of sources is not exactly one.

**Acceptance Criterion:** With a fake store: same and different against an environment variable, same against a file and against the credential of a git remote; a missing secret, a missing source and two sources exit 2; no output carries the value or more than a short status line.

### R2: Review nit of `safe run`

The position of a malformed `--env` is reported by its place in the list, not by the first equal argument.

**Acceptance Criterion:** A valid pair followed by a malformed one reports argument 2.

### R3: Knowledge written as public

The Epic identity states that everything in this Epic's `_grid4d` is written as if public (it may become public with the code): no plugged-in Epic content, no secrets, no instance specifics, Human rulings by meaning.

**Acceptance Criterion:** The rule is in the identity document.

### R4: Gaps of the safe model documented

A review of the target model with the Human found five gaps: processes without a login session (the OS store may be locked for a launch agent or service), recovery when the OS store is lost (by rotation, no value backup), expiry seen only when checked (a session-start check), the open choice of the git credential helper, and the agent boundary coming too late (it must precede the first wide-reach token). The question how ordinary work goes on (git, local database clients, tools with own configuration, CI) is answered by consumers by kind. The instance inventory and impact map (instance data, outside git, names only) were corrected: a pass by variable names missed variables templated from configuration files.

**Acceptance Criterion:** The safe blueprint carries the five gaps (known limits, later steps) and a table of consumers by kind; the story notes name the inventory correction and the method gap.

### R5: Safe first - the first open capability

Human direction (2026-10-25): safe handling of every credential is the first capability of ahabase and a mandatory precondition of every further step; it integrates the best existing tools instead of reinventing them, minimal own code at maximal function; it is offered as open source in the first open zone, not for profit - the community improves and shares it, the added value of ahabase comes in the further zones. The idea document holds the gap, a motivating scenario (a password shown on a shared screen by an agent), three layers of protection, the parts with the tools each builds on, the conditions before it is offered, open questions and the promotion path.

**Acceptance Criterion:** The rule is in the Epic identity; the idea document exists with those sections and links back to this story.

### R6: Links point inward

Human ruling (2026-10-25): documents of the open zone carry no links into the closed zone, only the information they need, extracted into them. The rule enters the Epic identity with its reasons (the direction of the code; one source of truth for every extract); the hand-written links of the current documents are replaced by extracts (a "Concepts in brief" section of the identity: Epic, Trust Zones); the two generators of the core that still write such links, and the missing check, are logged for the core.

**Acceptance Criterion:** A check over the current documents of this Epic (released stories excluded; the generated lines that still break the rule listed one by one by file and target, each tied to its issue; the check's own pattern line skipped) finds no link that does not resolve within the repository and no name of a closed-zone document; the rule and the issue exist.
