## Goal

Serves AHABASE-Priorities row 4 (trust: the trust-zone and containment checks run from ahabase) and the consumption-era MVP ruling (EVOLUCEAN-0555, Human 2026-11-20): the first public version carries the basics of rows 3+4+8, with **row 4 as the gate** — a standing machine-checked containment test over the exact built wheel+sdist, landing first so every later package change is guarded.

This story builds that gate and the two known leaks it already catches, plus the consumer-facing surface that lets a machine outside the private repos install and run the package:

1. **The standing containment scan** — allowlist + redaction + strict-subset over the whole wheel, redaction over the sdist, with the per-module canonicality pin (every shipped module byte-identical to its repo source, one canonical copy per module). It lands FIRST and is demonstrated RED at the pre-scrub baseline: it must catch the two real leaks before it is trusted to stand.
2. **The two docstring scrubs** — the keychain example string at `cli_safe.py:202` and `safe.py:353` (the only leak measured in the v0.0028 wheel).
3. **The consumer README section** — install and first commands for a consumer outside the private repos, with `env:NAME` documented as the Human ruled (option A): a documented CI/transitional exception, never a default, no removal story.
4. **The TestPyPI dry-run pipeline** — build, upload to TestPyPI, install into a clean venv from TestPyPI, import + doctor there. TestPyPI is allowed now; production publish and PyPI name reservation wait for the Human's explicit go.

Not here: the evolucean-copy deletion is a PARALLEL story, not a prerequisite — the gate pins per-module canonicality instead (EVOLUCEAN-0555 decision). The basics slice of rows 3 and 8 is the next shaping step, guarded by this gate once it stands.

## Requirements

### R1: The standing containment scan, red at the baseline

**Acceptance Criterion:** a test in the package suite builds the wheel and sdist from the story tree and scans them: the allowlist arm (every wheel file is on the pinned list — the package directory's `.py` sources plus the dist-info; a non-source file riding the package directory is a finding), the redaction arm (no match of the defined corporate-identifier patterns — the keychain example pattern, e-mail domains, internal hostnames — over the whole wheel and the sdist; a guard over the fixed pattern set, not a proof of no-leak) and the canonicality arm (every wheel file byte-identical to its repository source — the per-module canonicality pin as a build-consistency check: what ships is exactly the canonical tree; the cross-repo side, that evolucean delegates rather than forks, is guarded where it lives, by the evolucean census suites, not by this scan). Run at the pre-scrub baseline the scan is RED naming the leaks per artifact — the wheel: exactly the two known docstring leaks (`cli_safe.py:202`, `safe.py:353`); the sdist: those two plus the account number's occurrences in `tests/test_safe.py` — the gate proves it catches real leaks before it is trusted.

### R2: The two docstring scrubs

**Acceptance Criterion:** the account number is gone from every shipped occurrence — the two docstrings (`cli_safe.py:202`, `safe.py:353`) and the occurrences in `tests/test_safe.py` (the sdist ships the tests) — replaced by a neutral example, no behavior change; the scan's redaction arm is green on the scrubbed tree over both artifacts; and two mutants turn the scan red, both reverted: one reintroducing the known string into either docstring (both spots), one introducing a **different instance of the same class** (a second corporate e-mail domain or a different account id) — the class is what the arm catches, not the two measured instances.

### R3: The consumer README section with the env:NAME exception

**Acceptance Criterion:** the README gains a consumer install section — the install command (TestPyPI index for the dry run, written so the later public publish replaces only the index URL, not the section), the first commands a consumer runs outside the private repos (install, import, doctor), and `env:NAME` documented as a CI/transitional exception that is never a default and has no removal story (the Human ruling, option A). The example stays literally `env:NAME` — no token-shaped variable: the README ships in the sdist, its bytes ride the redaction arm. The scan carries an explicit negative test: the documented env example stays green (the arm guards corporate identifiers, not environment-variable documentation).

### R4: The TestPyPI dry run in a clean environment

**Acceptance Criterion:** a scripted pipeline builds the wheel+sdist, uploads to TestPyPI, and installs the package into a clean venv from TestPyPI; the installed package imports and doctor runs there (output in the Notes). Nothing beyond TestPyPI: no production PyPI upload, no name reservation, no repository create or rename — those wait for the Human's explicit go.

### R5: Release

**Acceptance Criterion:** the full suite and the three-platform matrix are green on the story branch (run id in the Notes).
