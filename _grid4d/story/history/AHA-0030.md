## Goal

Serves the consumption-era MVP ruling (EVOLUCEAN-0555, Human 2026-11-20): the first PUBLIC version of ahabase carries the basics of AHABASE-Priorities rows 3 (grid4d infrastructure), 4 (trust) and 8 (story) — a doors-only 0.x is not the first public release. The Human chose this slice as the next story the same day (chat 2026-11-20, "basics-slice rows 3/4/8").

"Basics" is the Human's word: the minimal working slice of each row, not the full migration (the dossier's own definition, section 2). This story is the shaping step the dossier left open (section 6): it defines and lands that slice, ordered as the dossier rules — **row 3 before row 8** (the story engine mints from the pattern core, so the core must stand first).

The design principle the Human set for the whole package (chat 2026-11-20): **ahabase is the opportunity for more robustness, more minimalism and less entropy than today's evolucean** — each capability lands simpler than the evolucean copy it precedes, not as a port of its accumulated layers. Its first concrete ruling: **identity self-registers through its def file in the consumer's repository — there is no parallel configuration** (no registry-as-plumbing layer in the public package; the def file `_grid4d/story/<EPIC>.md` with its `StoryPrefix:` declaration is THE registration).

What each row's basics mean here, from the measured surface (dossier section 2, AHA-0029):

1. **Row 3, the grid4d format core** — `_grid4d/` validation and the pattern engine live in ahabase behind the one registry: a consumer's Epic tree validates (knowledge folders, special folders, SubEpic inheritance, the identity file), and the story documents mint from the pattern templates. NOT here: the derived stores (DuckDB/Kuzu), sync, projections, sensors — evolucean-side depth that the full row-3 migration carries later.
2. **Row 8, the story lifecycle** — create, worktree, complete in the consumer's own Epic repository: mint a story with its tests/knowledge-map skeleton from the patterns, work it in its worktree, complete with tag + merge + archive. NOT here: the collaboration fabric (team log, seats, quorum — row 5), the counters CAS across instances, phases, karma.
3. **Row 4, trust basics — already standing**: the containment gate (AHA-0029) guards this slice like every later package change: the build runs the gate, the slice adds no unguarded surface, and the graduation checks (open-zone link check) run from the package.

Not here (parallel or later, per the AHA-0029 rulings): the evolucean-copy deletion for any capability (a parallel story once the full graduation happens, never a prerequisite); production PyPI publish and name reservation (the Human's go); rows 5-7.

## Requirements

### R1: The grid4d format core (row 3 basics)

**Acceptance Criterion:** the package carries a grid4d core that (a) validates an Epic's `_grid4d/` tree — the knowledge folders (`story/`, `ontology/`, `implementation/`, `pattern/`, `playbook/`, `issue/`), the special folders (`_archive/`, `_generated/`), SubEpic inheritance (a SubEpic inherits the root folders until it creates its own), and identity: the def file `_grid4d/story/<EPIC>.md` IS the registration — `**Type:** Epic` plus its `**StoryPrefix:**` declaration, read by the package's own epic loader with the prefix field ADDED to it (no registry; the yaml-registry arm of the evolucean copy stays out — the Human's ruling, 2026-11-20), and identity is SPLIT from the package declaration (`CodeArtifacts` is optional for the format core — the core never needs a code package to validate knowledge, checkpoint 0, seat c020eeb4); (b) reads the pattern templates the story engine mints from (epic, story, tests, knowledge map): a template is a WHOLE FILE, first match wins — the Epic's own `pattern/` folder before the package default, which is a name-neutral package resource looked up last and overrides nothing; the same fixed placeholder set everywhere, unknown names verbatim (no per-key merge — the minting path has none, checkpoint 0, seat c020eeb4); the patterns are also THE one home of the document-type map (which structural checks run on which document-name pattern) — no settings or config layer beside them, one home per rule (checkpoint 0, seat d2014bf4: the config-backed type map of the evolucean copy is the layer the self-registration ruling leaves behind); the default templates ship as package data pinned explicitly in the containment allowlist, canonicality-checked like the `.py` sources (the one named allowlist extension R3 carries — not python-string templates); and (c) reports a tree that violates the format namingly (folder, file, rule — the class of violation, not just a boolean; fail-closed; validation never writes): an unknown or misnamed knowledge artifact is a REPORTED finding (new surface, not a port — the evolucean copy silently ignores a document no type matches), naming is checked statelessly in-tree (fresh, not the store-backed debt counter of the evolucean copy), and the story-naming pattern DERIVES from the def file's `StoryPrefix:` declaration — never a hardcoded prefix literal (a containment and a self-registration violation in a public package); (d) resolves in-tree links by CALLING the package's own open-zone link check (`containment.compute`) — one implementation, two entry points — with its coverage stated as what it is: rendered links only (fenced blocks and code spans are stripped before resolution), so the naming-without-linking form is not covered and the slice does not claim it. Measured on a scratch consumer Epic in a clean environment: a valid tree passes, and each of at least three seeded violations (an unknown knowledge folder, a misnamed knowledge artifact, a missing identity file) is reported with its location. No store, no sync, no projection, no registry file, no config-backed type map — validation and patterns only.

### R2: The story lifecycle (row 8 basics)

**Acceptance Criterion:** the package carries a story engine that, in a consumer's own git repository, (a) mints a story: derives the next number by SCAN (the max across `story/` including `history/` and the live story worktrees — never stored, no counters branch, checkpoint 0, seat c020eeb4), creates the worktree + branch (`feature/<STORY>-short-desc`), writes the story set (story, tests, knowledge-map skeletons) from the R1 patterns; (b) shows status: active story, open stories, completed count; and (c) completes: verifies the story set exists, tags `v<version>` at the head, merges to the consumer's main, archives to `story/history/` (keeping the configured window), and removes the worktree. Measured end to end on the scratch consumer Epic: create → one document edit → complete leaves main tagged, merged and archived, and a re-run of create mints the next number. No collab, no team log, no phases, no counters branch — the local lifecycle only.

### R3: The slice rides the standing containment gate (row 4 basics)

**Acceptance Criterion:** the full build (wheel + sdist) of the slice-carrying tree passes the AHA-0029 containment scan with 0 findings — the gate runs unchanged over the grown package (the new modules are members like any other, no exemptions, and the allowlist pins grow only by what the build genuinely ships), and the R1/R2 surfaces carry no corporate-identifier bytes (the composed-vocabulary practice, AHA-0029 review F1). A mutant check proves the gate still bites on the grown surface: one seeded identifier-literal in a new module turns the scan red.

### R4: The consumer proof, outside the private repos

**Acceptance Criterion:** a consumer leg runs with no access to this workspace, proven by construction (checkpoint 0, seat b39ec132): the script runs with `HOME` pointed at a throwaway directory and `AHABASE_WORKSPACE`/`AHABASE_CONFIG`/`AHABASE_HOME` unset — the documented env keys are the experiment's controls, not its result — so every home-default path of the shipped code (the workspace default `~/ahabase`, the settings resolution, the trusted manifest, the llm path probing) lands inside the sandbox, and isolation is asserted after the leg: a snapshot of the throwaway `HOME` gained no files outside the leg's own directories. The clean venv installs the BUILT WHEEL (never `-e`, never `pip install .` from the tree), every leg command runs with cwd outside the source tree, and `pip show ahabase` + `ahabase --version` printed into the Notes witness which distribution ran. `ahabase` initializes a scratch Epic in a fresh git repository (the self-registering identity file, the folder skeleton), runs the R1 validation on it (green), and the no-parallel-configuration ruling is measured as ABSENCE, not said: after each step (init, validate, create, complete) the script inventories the scratch repo (a sorted find) and diffs it against a declared allowlist — any path outside the allowlist fails the leg, and the init allowlist is small enough that a registry file appearing anywhere (a yaml, a json state) turns the row red immediately. The R2 lifecycle runs end to end (create → edit → complete) with the git evidence in the Notes (tag at head, merge to main, archive move, a re-run of create minting the next number). The leg is fail-closed, not green-only: each of the three seeded R1 violations must exit NONZERO with its naming report, and the script's exit 0 depends on those expected-failure steps failing (a validator that is simply not wired must not pass a green-only leg). One script, exit 0, output in the Notes. Nothing in the leg reads `~/ahabase`, the private repos, or the enterprise network; no TestPyPI re-upload, no PyPI name reservation, no evolucean-copy deletion — all ruled parallel or awaiting the Human's go.
