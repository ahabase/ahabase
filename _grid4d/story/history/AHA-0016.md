# AHA-0016: ahabase capabilities: declare them, tag the code, gate verify, bridge the vocabulary

> The ahabase Epic gains the capability vocabulary the method CLI already has: a declared taxonomy, code that carries it, a verify gate that enforces it, a bridge that makes the evolucean Concepts projection read the truth, and the open-zone link check as a permanent capability of the package.

**Type:** shaping
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** [implementation-story-blueprint](implementation-story-blueprint)

## Goal

ahabase (the Epic) speaks capabilities the way evolucean does, but in its own vocabulary: the ontology declares what the package can do, every module names its capabilities, `ahabase verify` refuses an undefined capability, the cross-CLI vocabulary gap (Implements vs Blueprint) is bridged so the method's Concepts projection reads ahabase grounding truthfully, and the open-zone link rule is enforced by the package itself instead of per-story test scripts.

## Requirements

### R1: Capability taxonomy in the ontology

The ontology gains `ontology-capabilities-index.md`: the taxonomy of the package's capabilities, grouped into areas, every entry a `- **capability-name** → [concept](ontology-concept-blueprint) — description` bullet pointing at a concept blueprint that exists in this repository. No capability is declared free-floating: each maps to a concept.

**Acceptance Criterion:** `_grid4d/ontology/ontology-capabilities-index.md` exists, follows the evolucean index shape (Type: Ontology Index, Taxonomy of areas, bullet entries), and every `→ [x](x)` target resolves to an existing concept blueprint of this repository (measured by the R5 link check, green on the real tree).

### R2: The code carries its capabilities

Every module of `src/ahabase/` names its capabilities: each click command docstring carries a `Capability: <name>` line, and each service module carries the capability lines of the functions it exports. Every name used in code is defined in the R1 index.

**Acceptance Criterion:** all 13 modules of `src/ahabase/` (the eleven the story opened with plus the two gates it added, capabilities and containment) carry at least one `Capability:` line in their text - the population includes `__init__.py` (cli-command) and the platform shims `_posix.py`/`_win.py` (platform-dispatch), which name real capabilities rather than being exempted; the set of names in code is a subset of the index names (measured by the R3 gate, green on the real tree).

### R3: Capability gate in `ahabase verify`

`ahabase verify` gains the capability check, generic like the rest of the door: it resolves the Epic from `--root` (default cwd), reads the code artifacts the Epic's identity declares, extracts `Capability:` names, and reports every name missing from that Epic's capabilities index as a finding (exit 1). No ahabase-specific path is hardcoded — the check works on any Epic that declares CodeArtifacts and an index.

**Acceptance Criterion:** on the real tree `ahabase verify` holds (exit 0, no capability findings); on a scratch copy with a planted `Capability: no-such-capability` line the same command exits 1 naming that capability (red control asserted landed before the run).

### R4: Vocabulary bridge — the Concepts projection reads the truth

The method CLI's Concepts projection grounds a blueprint when a module's text carries a `Blueprint: <stem>` reference (`CODE_BLUEPRINT_RE` in `concepts_chain.py`, whole-file scan; `__`-prefixed files are skipped, and only the first target after each `**Implements:**` marker of a blueprint counts as its concept - measured by the reviewer at the baseline, which is why the flip set is five cells and not more); ahabase modules write `Implements:` instead, so the generated ``AHABASE-Concepts`` page shows Grounded 0/1 for door, lineage, portability, store and 0/2 for safe-value while all modules carry their links. The bridge lands ahabase-side: each module that today carries an `Implements: implementation-ahabase-<x>-blueprint` line also carries the same stem as a `Blueprint:` line — one vocabulary in the docstring, readable by both CLIs. The store cell needs one truth fix with it: the git credential helper's part of `implementation-ahabase-safe-integration-blueprint` is built (AHA-0013, the read-back glue in safe.py), so that blueprint's `**Code:**` line stops saying "none (document blueprint)" and names safe.py. The evolucean-side alternative (teaching `concepts_chain.py` the `Implements:` spelling) stays out of scope, logged as the cross-repo half.

**Acceptance Criterion:** the evolucean Concepts projection regenerated against this Epic's tree (calling tree wins) reads, measured against the 2026-10-31 00:11 baseline: door 1/1, lineage 1/1, portability 1/1, store 1/1 grounded, safe-value 1/2 (the docs-only threat-model blueprint stays honestly ungrounded), Fully grounded 4/19 (from 0/19); `ahabase verify` still holds with the added lines (the ahabase BACK_LINK check is unaffected).

### R5: Open-zone link check as a capability of the package

The containment half of [open-zone-documents-link-into-the-closed-zone](open-zone-documents-link-into-the-closed-zone) moves from per-story test scripts into the package: `ahabase verify` checks that every markdown link `[text](target)` of the Epic's `_grid4d` documents (excluding `story/history/` and `_archive/`, which are not scanned; documents there still resolve as targets) resolves within this repository or rides the declared generator exception. Resolution accepts three forms, all present in the real tree: a name-only target matching a document's stem, a `.md`-suffixed name, and a relative path that resolves from the linking file. What is scanned is rendered text: fenced code blocks and inline code spans are stripped first (the same not-a-link reading as evolucean's `strip_code_fences` precedent). The exceptions are generator-written only, each tied to its issue: the story-header blueprint name and the issues page's three Related-block names ([open-zone-documents-link-into-the-closed-zone](open-zone-documents-link-into-the-closed-zone), gaps 1 and 3), and the knowledge-map hook's rows that declare themselves - a path-prefixed target (another repository's document, [knowledge-map-links-a-document-of-another-repository](knowledge-map-links-a-document-of-another-repository)) or the row's own `(Generated)` kind marker (this Epic's ignored generated page: present on a synced tree, absent from a fresh clone). No hand-written allow-list: the two hand-written offenders of the reviewer's inventory (a notation example in the transparency blueprint, a Related link in [story-tests-run-at-line-must-stay-bare](story-tests-run-at-line-must-stay-bare)) are fixed in the documents, not exempted.

**Acceptance Criterion:** on a synced tree and on a clean checkout of the committed HEAD (`git archive` - the gate's green must not depend on ignored files being on disk) `ahabase verify` holds with the declared exceptions (the exception count reported names how many rode); on a scratch copy with a planted hand-written link to a document of another repository the same command exits 1 naming the file and the target (red control asserted landed before the run).
