# AHA-0022: Per-account gh login

> A `gh-login` target per GitHub account, in its own gh config directory under `_config/ahabase-gh/<account>`, written and verified only by the safe; the token stays in the keyring.

**Type:** default
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** [implementation-story-blueprint](implementation-story-blueprint)

## Goal

One instance can use two GitHub accounts on the same host. On the work instance, the tool Epics (evolucean, ahabase) run under one account, and the enterprise Epics run under another. Each Epic declares its account in its identity (`GitHubAccount`), and the safe holds one secret per account (`github-<account>`, stored 2026-11-06).

The safe's `gh-login` target writes the single gh login of a host. That is the extension point EVOLUCEAN-0528 documented and deliberately did not build ("the second account's own secret carries its own gh-login target and the caller names it"). `gh` cannot be a bound consumer of `ahabase safe run`, because it takes its destination from its arguments (measured 2026-11-06: the bind is refused).

The Human decided on 2026-11-06:

- each account gets its own gh config directory, `<workspace>/_config/ahabase-gh/<account>`, inside the instance configuration folder;
- the safe is the only writer of that directory and verifies it as it verifies the default login today;
- callers (first: the story lifecycle reading of EVOLUCEAN-0547) set `GH_CONFIG_DIR` from the Epic's `GitHubAccount`;
- a missing login is a note and stops the call, never a fallback to another account.

The work is started now, so that problems are solved as they come, not deferred.

## Requirements

### R1: gh-login target per account

`ahabase safe target add NAME gh-login-account HOSTNAME ACCOUNT` registers a login whose gh config directory is `<workspace>/_config/ahabase-gh/<ACCOUNT>`; `refresh`, `present` and `verify` run with `GH_CONFIG_DIR` set to it, with the token variables dropped as today. A distinct kind, not a field on `gh-login` (home-5235 F1): an older ahabase refuses an unknown kind, where it would ignore an unknown field and write the account's token into the host's default login. `gh-login` is unchanged. `ahabase safe gh-config-dir ACCOUNT` names the directory, so callers never form the path (F6).

**Acceptance Criterion:** two targets on two accounts on github.com hold their own logins; `verify` of each compares its own token; the default target is unchanged.

### R2: The token never in the directory

gh stores the token in the keyring; when no keyring is available it writes the token in plain text into `hosts.yml`. After every write the safe checks the directory for the secret's value (primary, any field name - F2) and for the `oauth_token` shape (secondary). A plaintext token makes the safe remove the file and fail with the remedy, naming gh's own exit code when it failed too (F3).

**Acceptance Criterion:** a fixture gh that writes `oauth_token` into `hosts.yml` makes `refresh` fail and leaves no token file; the normal keyring write passes.

### R3: The directory location

The workspace root comes from the instance, never a hard-coded home path (the open-source ahabase runs on any instance). The directory is created by the safe with owner-only permissions.

**Acceptance Criterion:** a fixture workspace gets its directory under its own `_config/`; the mode is `0700`.

### R4: Measured on the work instance

Both accounts are registered as targets and refreshed from the stored secrets. `GH_CONFIG_DIR=<dir> gh api user --jq .login` names the right account for each.

**Acceptance Criterion:** the two logins are measured in cross order (each re-checked after the other was written - F5: a host-keyed keyring would collide), and a shadow compare of each secret with its current source reads `same`.

### R_team: Improve team-work quality (standing requirement)

Team-work friction and improvement ideas surface during the work and are logged live to `_grid4d/issue/` and `_grid4d/idea/`.

**Acceptance Criterion:** Team-work quality observed and acted on during this story; friction is logged as issue or idea docs referencing the story, and no collaboration failure stays silent.
