# AHA-0001: Architecture and package skeleton: open ahabase package with registry for CLI, MCP and Claude Code plugin; evolucean core as entry-point plugin

> The first story of the ahabase Epic: the architecture accepted by the Human on 2026-10-24 written down, and the smallest package that proves it - one registry behind the doors, the core plugging in from outside.

**Type:** default
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** implementation-story-blueprint

## Goal

The Human (2026-10-24) accepted the architecture "the open ahabase package never calls the closed core; the core builds on the package and plugs in as a plugin" and asked for the repository `ahabase/ahabase` (private until the first release, Apache-2.0). This story records the architecture as the Epic's blueprint and builds the skeleton that makes it testable: a pure-Python package with the `ahabase` CLI, a registry of commands that plugins fill through Python entry points, and the guards every commit of this repository needs. The MCP server and the Claude Code plugin are named in the architecture and get their own stories; secrets come next (EVOLUCEAN-TRUST-0002, built in this package).

## Requirements

### R1: Architecture blueprint

`_grid4d/implementation/implementation-ahabase-architecture-blueprint.md`:
layers (doors, open package, closed core), the dependency rule (the core
imports the package, never the reverse), the plugin contract (entry-point
group, what a plugin may register, versioning), one registry behind every
door (CLI commands now, MCP tools later), zone placement (open package =
Public perimeter, core = Core circle, secrets = Intimate values behind an
open interface), and the order of the next stories. The **surface rule**:
in this repository the core is described only by its surface (command
names, the plugin contract), never by how the method works.

**Acceptance Criterion:** The blueprint exists with these sections and
passes the document validation of the Epic.

### R2: Package skeleton

`pyproject.toml` (hatchling, Python >= 3.11, Apache-2.0), `src/ahabase/`
with `__version__`, the `ahabase` console script (click) with `--version`
and `ahabase doctor`, `.gitignore`, `README.md` (private-until-release
note). `doctor` checks only the package and its plugins (Python, package
version, each plugin's origin, API version and load state) and runs the
health checks plugins register - it never duplicates a check a plugin
owns (one place per capability: `knowledge-usage doctor` stays the
core's).

**Acceptance Criterion:** In a fresh virtual environment `pip install -e .`
gives `ahabase --version` and `ahabase doctor` with exit code 0.

### R3: Plugin contract

`ahabase.plugins`: discovers entry points in the group `ahabase.plugins`;
each plugin exposes `register(registry)` and adds click commands and
health checks (MCP tools later through the same registry). Robustness:
- **API version** - the registry has an API version; a plugin declares
  the major version it needs (`API_VERSION`); an incompatible plugin is
  not loaded and is reported;
- **name collisions** - a command name already taken is not overwritten;
  the collision is reported;
- **failure isolation** - an exception in a plugin's import or `register`
  is caught, reported by `doctor`, and the CLI keeps working;
- **trust** - installing a plugin means trusting its code; `doctor` shows
  each plugin's distribution and version so the user sees what runs;
- the package imports nothing of any plugin.

**Acceptance Criterion:** A fictional test plugin adds a command that
`ahabase --help` lists and runs and a health check `doctor` runs; a
plugin whose `register` raises, one with an incompatible API version and
one whose command name collides are each reported by `doctor` while the
CLI still works; a static check finds no import of `evolucean` or
`knowledge_usage_cli` in `src/ahabase`.

### R4: Guards of this repository

This repository's side only (a story changes one repository): the dbt
pre-push hook installed by `epic init` is removed (this is no dbt

pattern was not inherited, so `story create` minted none); until the
story guard finds the evolucean CLI from another repository, the
containment check is run by hand on every push of this story (recorded
in the notes). The evolucean side - the guard's CLI lookup, the root
pattern inheritance, `epic init` (prefix option, no dbt hook outside dbt
projects) - is a parallel story of [EVOLUCEAN-DISTRIBUTION](EVOLUCEAN-DISTRIBUTION).

**Acceptance Criterion:** `.git/hooks/pre-push` is not the dbt hook; the
tests document of this story exists and runs; `containment check
--range` over this story's commits is clean.
