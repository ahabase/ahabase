# AHA-0015: ahabase projections: declare a minimal set, generate, check the open zone

> ahabase projections: declare a minimal set, generate, check the open zone

**Type:** shaping
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** implementation-story-blueprint

## Goal

AHA-0009 declared no page of the method's generator for this Epic (`projections: []`): no page's output had been checked against the rule that the open zone names no document of a method. Meanwhile the 27.10 drift files (since deleted, untracked) showed what happens in a tree without a declaration: the sync tail falls back to the full set. This story opens the zone the measured way - declare the minimal set whose pages carry only this repository's own content, prove the generation before merge by driving the generator's own API against this worktree (the CLI command resolves the workspace tree, which the story guard holds), and add the link check the open-zone issue names as this Epic's interim enforcement: every link of every generated page resolves within this repository, or is listed by file and target here and tied to that issue.

Measured before this story (scratch copy of the main tree, generator API): with `projections: []` the generation call writes 0 pages; with `projections: [concepts, issues]` it writes exactly `AHABASE-Concepts.md` and `AHABASE-Issues.md`; the Issues page's Related block names three method implementation blueprints (the closed-zone exception this story must list); the Stories page was tried and left out - the sync tail builds the ticket prefix from the repository name (`AHABASE-`) while this Epic's tickets are `AHA-`, so the page asserts `0 completed, 0 open`, a falsehood in the open zone.

## Requirements

### R1: The minimal declaration

**Acceptance Criterion:** `ahabase-projections-pattern.md` declares `projections: [concepts, issues]` - names valid per the registry's list - and its prose says, in plain words: what each declared page carries; that `stories` is not declared because the sync tail derives the ticket prefix from the repository name and this Epic's tickets are `AHA-` (issue [story-prefix-derived-from-repo-name](story-prefix-derived-from-repo-name)), to be declared when the generator learns the Epic's own prefix; that a tree without this declaration file gets the full set (the fallback that produced the 27.10 drift), so the declaration merges with this story and the window closes; and that every closed-zone name a generated page carries is listed in this story's link check and tied to [open-zone-documents-link-into-the-closed-zone](open-zone-documents-link-into-the-closed-zone).

### R2: Generation proved before merge

**Acceptance Criterion:** A test row drives `ProjectionRegistry.generate_all` - the same call the sync tail makes - with an `Epic` bound to this worktree: exactly the two declared pages are written under `_grid4d/_generated/epic/` and no other page appears there (the generator's own `.projection-health.json` health sidecar sits beside them). The Concepts page carries this Epic's concepts with their blueprint column (portability among them) and links the ontology index; the Issues page lists this story's new issue - the page reflects this tree, not a stale one. Red control: on a scratch copy of the tree with the empty declaration restored, the same call writes no page and creates no generated dir (the declaration gates writes - it does not sweep stale pages; pages left behind are R4's orphans).

### R3: The open-zone link check

**Acceptance Criterion:** A test row extracts every wiki-style link from each generated page and resolves each within this repository's `_grid4d` (story, story/history, ontology, implementation, pattern, issue, idea); every unresolved target is a listed known exception, and every listed exception occurs on its page (no stale rows). Known exceptions today, all on `AHABASE-Issues.md`'s Related block, tied to [open-zone-documents-link-into-the-closed-zone](open-zone-documents-link-into-the-closed-zone): `implementation-cli-projections_epic_issues-blueprint`, `implementation-cli-issue_matcher-blueprint`, `implementation-cli-sensors-blueprint`. Red control: a link planted into a page copy that resolves nowhere turns the check red.

### R4: Declarations satisfied

**Acceptance Criterion:** `declarations check --epic-root <this worktree>` exits 0 and reports the Epic satisfied with the declared count. Red control: with one declared page removed on a scratch copy, the check reports DRIFT and exits non-zero. The story records the post-merge expectation: the next sync of the main tree generates the declared set there through the same tail, and no fallback remains.

### R_team: Team-work quality

**Acceptance Criterion:** Review seats addressed by session, verdicts recorded with their commit; friction logged as it happens.

### R_docs: Documentation

**Acceptance Criterion:** The declaration's prose covers every rule above; the two issue files carry the findings (the prefix derivation for the method's owners, the new generator surface on the open-zone issue); the method's zone is not written into from here.

### R_issues: Issues

**Acceptance Criterion:** Every problem met is fixed or logged: the prefix derivation, the Issues-page Related block and the declarations-check fail-open get issue files; the 27.10 drift cleanup is recorded here (untracked files deleted, nothing tracked lost).
