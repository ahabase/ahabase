# AHA-0005: safe research: existing tools per concept - stores, scanners, git credential helpers, agent guard and output watch; integrate-or-write decisions

> Before any further code of the safe: which existing tool each part integrates and what little remains as own glue - and an honest answer to what an agent's hooks can protect.

**Type:** default
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** [implementation-story-blueprint](implementation-story-blueprint)

## Goal

The Human ruled (2026-10-25) that the safe integrates the best existing tools instead of reinventing them, minimal own code at maximal function, and that each tool is evaluated before own code. This story compares the available tools for each part of the safe - the scanner, further stores, the git credential helper, the agent guard and the output watch - and records an integrate-or-write decision per part, mapped onto the concepts of the ontology. No code is written; nothing on the instance changes.

## Requirements

### R1: Comparison per part

For each part the tools are compared by licence, maintenance state, platforms, how they are invoked, whether they work offline and whether their output can be limited to names and places; facts not checked on the project's own pages are marked unverified.

**Acceptance Criterion:** The integration blueprint has a comparison for the scanner, the stores, the git credential helper, and the agent mechanisms with the vendor offerings for agents.

### R2: Decisions

Each part has a decision - integrate which tool and how, or write which glue - with its reasons, under rules that make the choice repeatable (integrate before writing, offline by default, own reduction of output, licence fit, re-check before building).

**Acceptance Criterion:** Each of the four parts has a Decision paragraph; the blueprint's Rules list the five rules; the safe blueprint names the git helper decision.

### R3: The reach of agent hooks

What the agent's mechanisms can do is established from its documentation, and the consequence for the motivating scenario (a value on a shared screen) is stated: hooks after a tool call change only what the model sees, so the screen is protected only before the command runs.

**Acceptance Criterion:** The blueprint states the reach of permission rules, the sandbox, the pre-call and the post-call hook with their limits, and the consequence; the Output Watch concept and the idea say the same.

### R4: The idea's open questions

**Acceptance Criterion:** The idea lists which open questions this story answered and which remain open; its promotion path marks the research step done.

### R_team: Team-work quality

**Acceptance Criterion:** One review round on both instances with a 45-minute deadline and content frozen during the round; every verdict recorded with its commit; friction logged.

### R_docs: Documentation

**Acceptance Criterion:** The integration blueprint, the safe blueprint, the idea and the concepts agree.

### R_issues: Issues

**Acceptance Criterion:** Every problem met is fixed or logged.
