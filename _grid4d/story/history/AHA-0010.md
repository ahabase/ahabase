# AHA-0010: Identity states Infrastructure true (EVOLUCEAN-0518 follow-up)

> The ahabase identity says that ahabase is part of the shared infrastructure, so that fact no longer lives only in an instance's registry.

**Type:** default
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** implementation-story-blueprint

## Goal

EVOLUCEAN-0518 R6 makes the identity documents the one source of what describes an Epic; an instance's configuration keeps only what belongs to the instance. Whether an Epic is part of the shared infrastructure (open by design, so the content-containment check treats its names as shared) describes the Epic. Today the work instance's registry carries `infrastructure: true` for ahabase and the identity says nothing. This story writes the fact into the identity, before the evolucean reader switches to it.

## Decisions

- **Order of landing:** this identity field lands before the evolucean change that reads it. The released evolucean CLI reads `infrastructure` from the registry only and ignores the identity field, so this story changes nothing on its own. Once the reader moves to the identity, an identity without the field would make ahabase's names foreign to the containment check.
- **Not inherited:** the field names the Epic itself, so the evolucean reader does not pass it from an ancestor to a descendant.
