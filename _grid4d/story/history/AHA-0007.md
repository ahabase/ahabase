# AHA-0007: safe hardening: consumer binding by absolute path, minimal child environment, reveal and compare by a person only, manifest protection; threat model gains development versus operation

> The code side of closing the agent path - values reach only bound consumers with a minimal environment, reveal and compare are the owner's - built so that it never locks the owner out.

**Type:** default
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** implementation-story-blueprint

## Goal

The threat model puts the agent path first. This story builds its code side in the package: consumer binding, the minimal child environment, reveal and compare by a person at a terminal, the protection of the manifest and its override variables. The Human ruled on 2026-10-25 that security, simplicity and reliability of use are equal requirements - a leak and the loss of access to a service are both failures - so every control comes with its owner's way through. The threat model first gains what the Human's questions about git, the forge CLI, databases and messaging revealed. The agent guard (permission rules, sandbox, hooks) is the next story; nothing on the instance changes here.

## Requirements

### R1: Threat model - new findings and the equal requirement

Development versus operation (a bound consumer is a released, installed version the agent cannot change; a worktree copy is never bound), the agent guard's denial of other tools' credential-printing commands, refused redirecting options and installed commands instead of interpreters in the binding rules, bindings that survive package upgrades (measured: a package manager's real paths carry the version), a working base environment with proxy and certificate settings, a new threat T12 (lockout by the safe's own controls) and rule 5 (security, simplicity and reliability are equal).

**Acceptance Criterion:** The threat model carries T12 with its seven designed controls, rule 5, the extended T2 binding rules and T9's development versus operation; the identity's Safe first rule names the equal requirement.

### R2: Consumer binding

`ahabase safe bind NAME /absolute/path [--prefix ARG] [--allow OPTION]` and `unbind`; `safe run` refuses, before any value is read, a command that is not bound by its absolute path, whose real target left the recorded package root, whose arguments do not start with the prefix, or that carries a redirecting option not allowed; shells, interpreters, wrappers and general-purpose network tools cannot be bound; every refusal names the command that proceeds.

**Acceptance Criterion:** Tests: the not-bindable kinds refused with the way through; an unbound command refused with no value read; an earlier executable on `PATH` refused; a binding survives an upgrade inside the package root and is refused after a move elsewhere; prefix and redirecting options enforced and allowable; unbind withdraws.

### R3: Minimal environment, shell-free

The child gets the base environment (including proxy and certificate settings), the kept variables and the named values - no other exported value; `safe run` executes an argument list, pinned by a test.

**Acceptance Criterion:** Tests: another exported value is absent in the child while the proxy setting and a kept variable are present; the executed call is a list without a shell.

### R4: The owner's commands

`get --reveal` and `bind` need the owner at a terminal typing the name; `compare` needs a terminal and a confirmation and refuses more than five comparisons of one name within a minute.

**Acceptance Criterion:** Tests: refused without a terminal, refused with a wrong name, accepted with the right one; five comparisons pass, the sixth is refused with the way through.

### R5: Manifest and override protection

The manifest is never written inside a git working tree; `safe run` with an override variable set needs the owner's confirmation; `doctor` reports a set override variable and a bound consumer that vanished. The test suite isolates through `HOME` alone, as production runs.

**Acceptance Criterion:** Tests for each; the whole suite passes with the override variables cleared.

### R_team: Team-work quality

**Acceptance Criterion:** One review round on both instances with a 45-minute deadline, content frozen, waiting on verdicts (not replies); every verdict recorded with its commit; friction logged.

### R_docs: Documentation

**Acceptance Criterion:** Safe blueprint (rules 4, 5, 8-10, template, example), README, the concepts' states and the threat model's today-lines match the code.

### R_issues: Issues

**Acceptance Criterion:** Every problem met is fixed or logged.
