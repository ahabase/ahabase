# AHA-0033: ahabase engine architecture

> The public ahabase package redesigned as the complete engine - the layer model, the capability fate map, the workspace skeleton, and the state invariant every later story builds against.

**Type:** shaping
**Epic:** [AHABASE](AHABASE)
**Status:** completed
**Blueprint:** [implementation-story-blueprint](implementation-story-blueprint)

## Goal

The 2026-11-22 Human ruling sets the direction: the public ahabase package must be fully functional like today's evolucean CLI - the minimal-consumer cut went below the usability boundary (measured: 8 package doors vs ~50 evolucean command groups, and the `trust` door missing entirely, below even the rows-3-4-8 basics ruling). This story turns that ruling into one architecture document: the contract future stories build against, the record of the evening's architecture decisions, and the explicit list of what is still open. No code moves in this story - the worktree relocation, the wiki door, and the door migrations it sequences are follow-up stories that cite this blueprint.

## Requirements

### R1: the layer model

The blueprint defines the four layers and the private residue: doors (CLI, MCP, Claude Code plugin - plugins over seams, growth is a new door, not engine surgery), engine (the full game: story lifecycle, grid4d documents machinery, trust and collab, status/sync, projections, snapshot, release, llm, safe), substrate (OPTIONAL heavy stores - usage DB, Kuzu, MQTT broker, proxy - additive: add-on doors with their own install extras, never prerequisites, never dual-mode doors, rule 12), and workspace (repos anywhere, def-file identity, engine-owned local state). The private residue names what stays out of the public package and why (enterprise bridges, this machine's sensor/wake fleet).

**Acceptance Criterion:** The blueprint states each layer's ownership: what lives in it, who writes it, and one worked example per layer drawn from the measured census.

### R2: the capability fate map

Every command group of the measured evolucean census (the `--help` listing, 2026-11-22) appears in the fate map with exactly one decided fate: engine door / engine door over optional substrate / private (with reason) / dies with the migration.

**Acceptance Criterion:** The fate map covers every group in the census (grouped rows allowed, none omitted); each fate row is decidable - a reader can tell, for a named group, whether the public package will run it.

### R3: the state invariant

The blueprint replaces the over-cut "no state beside the tree" with the survivable invariant: trees + git are the only source of truth; everything in `_data/` and `_generated/` is a cache or an append-only journal - engine-owned, gitignored, rebuildable. For every state kind the blueprint names the command that rebuilds it.

**Acceptance Criterion:** The invariant section lists each state kind (journals, locks, projections, snapshots) with its class (cache or journal) and its rebuild command; nothing is named state without a rebuild path.

### R4: the workspace skeleton

`ahabase init` lays out the whole board with uniform anatomy across every installation (Home, the frozen Work copy, the playground, an open-source consumer): `_config/ _data/ _generated/ _inbox/ _temp/ _wikis/ _worktrees/`, each placeholder folder carrying a `_README.md` contract (what belongs there, who writes, rebuild policy). No placeholder without a writer.

**Acceptance Criterion:** The skeleton section specifies every folder: writer, content, gitignore and rebuild policy; the repo itself stays pure - tracked content only, no engine-written ignore lines.

### R5: the 2026-11-22 architecture decisions, numbered

The blueprint records the evening's Human rulings as numbered decisions with reasons: (1) worktrees live OUTSIDE the repo at `<workspace>/_worktrees/<epic>/<STORY>` - a worktree is local temporary structure and does not belong in the git repo structure; the engine never writes `.gitignore` lines or chore commits to hide its own local state (reverses the AHA-0031 in-repo choice; boundary: one workspace assumes one clone per Epic; the AHA-0032 lock is untouched - it keys on the common git dir, not the worktree location). (2) Wiki publishing is an essential engine door, not private practice: the `wiki` door migrates like the other groups, `_grid4d/wiki.yml` is engine format, `_wikis/` ships from init. (3) The public collab transport is MQTT - the fabric evolucean practice has proven - with team membership (trust join rows) staying on the collab git branch, also proven by practice; the same-day first draft of this decision (git journal as transport, MQTT as substrate) is reversed inside D3, and the standing strategy D4 (carry the proven, simplify, never invent) is recorded with it.

**Acceptance Criterion:** Each decision carries its reason and what it reverses or replaces; the amending effect on existing blueprints (notably implementation-story-lifecycle-blueprint rules 1 and 5) is stated as a target, not silently applied.

### R6: sequencing, folded ideas, open questions

The blueprint sequences the door groups toward the public flip (the fresh-start repo and the PyPI release, extending the rows-3-4-8 basics ruling), absorbs the three pool ideas as line items (shared-taxonomy-space - how large a knowledge slice the distribution carries; example-epic-in-distribution; pattern-override-discovery - making the Epic pattern override slot discoverable), and ends with the open-questions section: what this story deliberately does NOT decide.

**Acceptance Criterion:** The sequencing section names the door groups in order with the release each lands in; each of the three ideas appears as a line item with its disposition; the open-questions section lists at least the genuinely undecided items (substrate optionality mechanics, collab transport details, the fresh-start repo mechanics).
