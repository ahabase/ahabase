## Goal

The first two public release tags, v0.0035 and v0.0036, turned the Actions matrix red on the `windows-latest` lane only (macOS and Ubuntu green): 6 failed, 480 passed, 10 skipped at v0.0036 (run 45119425258), 3 failed at v0.0035. Every failure is portability of a test or of an output line, not product logic. A second oddity rides every completion: the main-branch run is always shown as cancelled. This story makes the Windows lane green and removes the cancelled-run noise, so a red release tag means a real defect again.

The Human asked for it on 2026-11-23 after reading the failed jobs, with the author seat (stream A, 44af88c3) unavailable; the diagnosis was sent to that seat first (chat seq 6121 and 6122). Seat 5ccb7069 (the author of this story) wrote it; the reviewers are the two standing seats.

Measured causes (job logs, then test sources at main c112940):

- `story status` printed the worktree location through `str(Path)`: Windows prints backslashes, two assertions expect forward slashes (`tests/test_story.py` lines 123 and 159).
- `test_r1cwd_one_lock_whichever_cwd` asserts that the repository holds exactly one lock file after release; filelock's Windows lock deletes the file on release, so the list is empty there (an AHA-0032 test, only ever measured on macOS).
- The stub `gh` of two wiki rows is a POSIX script named `gh`: Windows' `shutil.which` matches PATHEXT names only, so the runner's own `gh.exe` answered, ran with the scrubbed `GH_TOKEN` and failed.
- The pre-push hook witness wrote `env > <Windows path>` from `sh`; the backslash path is mangled and the witness file is never created.
- The cancelled main run: `concurrency: {group: tests-<ref>, cancel-in-progress: true}` (AHA-0034 round 1) puts the completion push and the following `chore: archive old stories to history/` push on one ref; the second cancels the first run after ~30 seconds. The tag run, the only one with the three-OS matrix, is on another ref and never cancelled.

## Requirements

### R1: the Windows lane passes

Four edits, each at its measured cause: `story status` prints a posix separator for the worktree location (a consumer-facing line is better stable than OS-dependent); the lock test asserts the invariant that holds on both platforms (nothing but the common lock path under the repository; none left on Windows after release); the wiki rows write the stub gh as `gh.cmd` on Windows and as the sh script elsewhere; the hook witness path is spelled posix inside the hook script.

**Acceptance Criterion:** a `workflow_dispatch` run of the story branch runs the full three-OS matrix and `windows-latest` concludes success (measured via `gh run view`); the six named tests pass on macOS in the story suite; the Windows failure list of run 45119425258 is empty.

### R2: a completion leaves no cancelled run

`cancel-in-progress` applies to feature branches and pull requests only; `main` and the release tags always finish. The group key stays `tests-<ref>`, so a PR and its push still do not double-spend (the AHA-0034 intent), and a superseded feature-branch run still cancels. The workflow keeps one pending run per group, so two quick main pushes both complete.

**Acceptance Criterion:** the workflow's concurrency expression is `cancel-in-progress` false for `refs/heads/main` and `refs/tags/*` and true elsewhere (the suite evaluates the expression on those three refs); the story's own completion produces two main runs and a tag run, none cancelled (measured after completion, recorded in the Notes).

### R3: the other half is named, not hidden

The completion flow's two quick pushes to main come from the operating engine (the evolucean `story complete`), outside this repository; the cure is one combined push there. That is recorded as an idea with its evidence, for the evolucean-story SubEpic, not built here.

**Acceptance Criterion:** an idea document exists in this tree naming the two pushes, the evidence (runs 45119412297 and 45119437351) and the two options (one combined push, or a guard for the archive-only commit).
