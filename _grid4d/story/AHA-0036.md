## Requirements

### R1: the wiki door lands (the migrated half)

The four proven operations land behind the ahabase CLI as one `wiki` door - `generate`, `sync`, `check`, `clean` - ported from the donor's six wiki modules into the engine's vocabulary and conventions: plugin contract intact (`API_VERSION`, `register(registry)`), the config read from `<workspace>/_config/<epic>.wiki.yaml` with the donor's defaults when the file is absent, the mirror at `<workspace>/_wikis/<epic>.wiki`, and no donor literals in `src/ahabase/*.py` (the test_plugins guard).

**Acceptance Criterion:** for the same fixture epic tree, the ahabase door produces the same wiki mirror shape the donor produces (page set, sidebar, home) - a suite row rehearses both polarities (config present with overrides; config absent with defaults) by comparing the two outputs.

### R2: the publish door (the built half)

A `wiki publish` operation completing the loop: the mirror clones the epic repository's wiki remote (`<repo>.wiki.git`) on first run and fetches on later runs, the synced delta commits with the wiki commit convention, and the push rides the safe's credential chain under the Epic's declared GitHub account (the fail-closed identity gate, remedy named). Refusals name their remedy (no wiki remote reachable, account mismatch, dirty mirror with a push pending) and never publish silently wrong.

**Acceptance Criterion:** publishing a fixture mirror to a throwaway local bare `*.wiki.git` remote succeeds end to end (clone/init, commit, push) and the pushed tree equals the mirror; a second run pushes only the delta; the refusal polarity (wrong-account guard) is rehearsed - all against local remotes in the suite, no live GitHub.

### R3: consumer surface, concept, and seam documentation

The consumer sees the capability: the playground CLAUDE.md names the wiki door and the publish flow for the `_wikis/` folder; the ahabase ontology index carries the concept (a capability lands only with its concept documented); the door sits in the one command registry under its capability name; and the seam surface is checked by test - the frozen five plus status (six subcommands) exit distinguishably per outcome, the contract the flip relies on.

**Acceptance Criterion:** the playground docs name the door and publish flow (grep row); the ontology index and the command registry carry the capability, and a suite row witnesses the seam surface (the frozen five plus status, distinguishable exits); no capability ships undocumented.

### R4: suite and cold CI before public push

The story suite measures R1-R3 with rehearsed rows (every leg standalone, both polarities), and the artifact's full test suite runs cold on the built export (fresh venv, wheel install, full pytest) before any public push - the standing public-push gate. Ends with a release (the floor the flip will pin).

**Acceptance Criterion:** story suite green; cold CI green with the passed count recorded in this story; the release tagged; the public repository receives the merge only after both.
