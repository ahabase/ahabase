# AHA-0034: public fresh-start repository

> public fresh-start repository

**Type:** default
**Epic:** [AHABASE](AHABASE)
**Status:** in_progress
**Blueprint:** [implementation-story-blueprint](implementation-story-blueprint)
**Follows:** AHA-0033

## Goal

The 2026-11-22 priority ruling (after GitHub reported 90 % Actions-minutes exhaustion on the day-old Team plan) sets creating the public repository as the first priority, and the goal name is the canonical `ahabase/ahabase`. The current private repository cannot be flipped (measured 2026-11-21: its history exposes personal and corporate account names, an internal mirror artifact, and the full development record), so this story walks the staging path: a private staging repository receives only scrubbed states, passes a measured scrub gate, flips public, and two org-internal renames leave the canonical name in public hands with the private history archived under `ahabase/ahabase-private`. Continuity is a first-class requirement, not a side effect: the story ledger carries, the instance journal is untouched, no collab branch exists before the flip, the Work machine is not targeted, and the operating engine remains the evolucean CLI (the self-hosting swap is sequenced by AHA-0033, not this story).

## Requirements

### R1: the private staging repository

Create `ahabase/ahabase-public` under the ahabase org as a PRIVATE repository with a fresh git root: no history transfer, no mirrors, no collab branch. The repository receives only what this story seeds through scrubbed pushes; the story itself develops in the current private repository (normal worktree flow). CI ships with the first seed push and is Linux-only on push - macOS and Windows run on tags or manual dispatch only (the org minutes pool is account-wide and already drained once; public repositories run free after the flip).

**Acceptance Criterion:** the canonical repository ends public and its CI workflow names ubuntu-latest only for the push path; the seed carries a fresh root (no transferred history).

### R2: the scrub gate

The seed content - package code (`src/ahabase`, tests, pyproject, docs, scripts), the story ledger (`_grid4d` including story history, minus the mirror-class generated artifact maps - publishing 74k lines of generated foreign-tree path listings would publish the lab's closed how, which the system's own what/why rule forbids; the private archive keeps the full record), and the CLI-read patterns - passes a measured scrub checklist before anything is pushed: no personal or corporate account names, no enterprise hostnames or schema names, no internal mirror artifact, no secret material (pattern scan plus a secret scanner). One measurement method covers baseline and seed alike (case-insensitive contiguous tokens, stems counting their longer forms - fixed at review round 1, when the round-1 zero proved to be a config-pattern zero while class members in other case forms and uncovered forms still shipped); the containment scanner's runtime-composed vocabulary is the guard's own mechanism and sits outside every class population by rule. The account-name literals themselves never enter committed files: the literal checklist lives in the uncommitted local config, and the committed record is the scrub report with counts per class (`AHA-0034-scrub-report.md`).

**Acceptance Criterion:** every checklist class appears in the scrub report with zero matches against the seeded tree, and the report rows are what the suite measures; a secret scan (gitleaks or GitHub secret scanning) is recorded clean.

### R3: the flip and the rename dance

Only after the gate is green: flip `ahabase/ahabase-public` to public; rename the private `ahabase/ahabase` to `ahabase/ahabase-private` (the archive: full history and every release v0.00xx stay, nothing is deleted); rename the public repository to the canonical `ahabase/ahabase`. The renames are org-internal, seconds apart, and move no data; GitHub redirects keep git operations and old links working through the transition. The published history keeps the maintainer identity (real name and personal address - an explicitly accepted non-goal, Human ruling 2026-11-22: open source shows its author); the R3 row pins exactly one author and one committer identity so no other identity can ride the public history unnoticed.

**Acceptance Criterion:** `ahabase/ahabase` is public with fresh-root history; `ahabase/ahabase-private` is private and still lists the v0.0033 release; both states verified via gh after the renames.

### R4: workspace rewiring and parity

The workspace switches to the public repository as the epic home: the local clone moves onto the public repository's fresh history (the canonical URL is unchanged by the renames - what changes is which repository it resolves to), `_config/ahabase.yaml` stays consistent, and the old clone is demoted to a read-only archive pointer. Completion of this story runs in the archive tree (its release v0.0034 is the last private release); the closing handover action is the final scrubbed export push that brings the public repository to parity with the completed story ledger - from AHA-0035 on, stories mint in the public repository.

**Acceptance Criterion:** the workspace epic tree sits on the public repository's fresh history and the public repository's story ledger holds this story's documents (verified after the handover push).

### R5: continuity guarantees

The migration changes no format and targets no other machine: the instance journal (append-only `_data` record) keeps its format and location; no collab branch exists in the staging/public repository before the flip - membership rows begin only on the fresh collab branch of the public repository when seats re-join (the branch-list measurement is read at the handover, before that re-join; the tests row states its read point, and a gh failure fails it); the Work machine is untouched (frozen consumer, deliberately out); the operating engine remains the evolucean CLI - the self-hosting swap waits for the story and trust door migrations sequenced by the architecture blueprint. The review of this story itself rides the archive repository's collab branch through the rename redirects.

**Acceptance Criterion:** each guarantee is either measured (branch list of the public repository at handover time) or stated in this story as an explicit non-goal with its blueprint citation; no step of this story renames a format, moves a journal, or addresses the Work instance.
